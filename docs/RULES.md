# 棋规覆盖与验收边界

规则参照：中国象棋协会审定《象棋竞赛规则（2020版）》。参考入口：<https://cnchess.net/rules/rules2020.html>。

本版本**没有完成第 8、9 章全部参考棋例认证，不能声称完全符合 2020 竞赛裁定**。界面、LAN 和 npm 包可独立使用，但“完整竞赛棋例”仍是正式发行前的未完成项。

## 已实现并有自动化覆盖

- 七类棋子的移动与吃子，九宫、河界、马腿、象眼、炮架、过河兵、禁止送将与将帅照面。
- 全部合法应对枚举；将死立即负、困毙立即负。双炮与马后炮都验证有解/无解局面，不能用动画阵形代替终局计算。
- 认输、协议和棋、双方仅剩将帅士象时的简单无进攻子力和棋。
- 提和限制：前 25 回合不可提和、自己回合提出、不可自行撤回、对方落子或拒绝视为拒和、次数最多领先两次。
- 自然限着：从最后一次吃子后计数，审核方将军最多计十着。
- 单方长将判负；已覆盖直接长捉循环及两回合变着警告，拒绝把所有三次重复统一判和。
- 中文记谱按双方视角计算，红方中文数字、黑方阿拉伯数字；支持前后、中与多兵同路消歧。

## 尚未完成的竞赛裁定

`src/core/adjudication.ts` 已与基础走法分开，但仍存在以下明确限制：

1. 杀着证明目前限于连续将军搜索，最多 5 层 / 6000 节点。正结果须有完整分支证明，搜索不确定时显示提示，不据此强判和或判负。不是任意深度的杀棋判定器。
2. 交换计算目前以同一目标格的合法连续互吃为基础；跨格牵制损失、连续将军得子、自毙、守和要点及兵卒浮动价值等例外未完成全面实现。
3. 双方均为攻击性循环时，需要第 26.9 条的无根/少根/联合捉子精确分类。当前显示待裁定提示，继续允许合法行棋或双方议和；不使用子力分数猜测输赢。
4. 第 23.4 条三点或更多点九回合交替攻击、非严格同序循环，以及第 23.5 的完整变着期限与前 25 回合“须有闲着”条件，仍需补齐参考棋例回归。
5. 当前重复局面识别是严格匹配的三轮着法循环，不能替代所有“待判局面”定义。

这些限制影响的是复杂竞赛棋例自动裁定，不影响普通移动是否合法、当前是否被将军、当前是否将死或困毙的完整合法应对计算。

## 继续完成的验收方法

逐一将第 8、9 章参考图转换为合法 FEN、固定着法与预期分类，保留条文编号和解释；先跑单着分类，再跑完整循环裁定。所有参考图通过后，才可移除上述限制说明与 npm `private` 发布保护。不要把未覆盖棋例标为通过，也不要用统一三次重复和棋替换。
